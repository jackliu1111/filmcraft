# #22 普通素材的连续声画剪辑轨

2026-10-16。原生代码已实现，自动回归和界面编译已验证；本票的实际鼠标操作、原生重启及默认导出由集成验收另外记录，尚不据此关闭工单。

## 用户入口

在空序列的视频轨名称区域右键，选择 **Use as Editing Track (A/V)**。它指定该视频轨及对应音频轨为同一条连续剪辑轨，不修改其他轨道的编辑规则。已有轨道只在从零连续、关联声画对齐时允许接管；独立人工音频不会被隐藏或覆盖。

从源面板使用原生 **Drag Video and Audio** 控件，或拖动画面，将当前源范围放入该轨。空白落点追加末尾，已有内容内的落点取最近剪辑边界并插入，后段声画一起顺延；一次撤销恢复整个放置及位移。Esc、无效落点继续走原生取消机制。

默认只有一条 **Editing · A/V** 展示行，底部展示关联声音波形；底层视频、音频及多路声音仍是原生 TrackItem。右键该行可选 **Show Associated Audio Tracks** 访问原生音频轨，或 **Use Native Track Editing** 清除角色。已独立移动、不再对齐的音频不折叠。

时间线和节目监视器标示 **Sequence**，源监视器标示 **Source**。剪辑轨头部显示当前成片播放头对应的原片时间；原生 **Match Frame / F** 可把源预览定位到对应原片帧，例如成片第 9 秒对应原片第 31 秒。源与节目播放头仍沿用原生的独立状态。

## 公共接口与复用点

- `sequence.setEditingTrack {track:"V1"|id,audioTrack:"A1"|id}`：指定当前序列的连续剪辑轨；省略目的轨时采用当前源映射。`{enabled:false}` 清除角色，保留片段。
- `timeline.place`：沿用原生 `item`/`items`、`sourceIn`、`duration`、`time`/`seconds` 等参数。原片范围使用 Tick；目标轨策略统一作用于普通素材和后续 AI 拖入。
- `timeline.planPlacement`：接受与单素材 `timeline.place` 相同的参数、仅针对已有轨道。纯查询返回实际 `time`、`duration`、`sourceIn`、`track`、`audioTrack`、`contiguous`、`insert` 以及 `shifts:[{clip,track,from,to,duration}]`。原生拖动预览与提交共享解析器及目标落点 planner，查询不创建历史步骤。
- `sequence.inspect.editingTrack`：`{video:id,audio:[id,...]}` 或 null。片段中保留 `item/sourceIn/sourceOut/start/end/link`，同时公开 `audioStream/sourceChannels`，便于检查原片到成片映射及保留音轨。
- 持久化字段为 `Sequence.editing_track: Option<EditingTrack>`，旧工程默认为无角色；`file.saveAs`、`file.save`、`file.open` 复用原生工程封装。没有为原片参照添加可渲染全长片段。

连续插入在一个原生工程编辑事务中复用 `insert_track_gap` / `overwrite`，只对角色拥有的轨道开空隙；不会触发其他原生 sync-lock 轨道顺延。额外声音输出新建专属原生音轨，避免占用相邻已有音轨。原生媒体池、预览、关联选择、撤销、保存和渲染导出沿用原路径。

## 操作定位

稳定自动化元素：

| 元素 | 用途 |
| --- | --- |
| `timeline.track.V1.menu`（或 V2 等） | 轨道名称区域，右键打开菜单 |
| `timeline.trackMenu.editingTrack` | 设置或清除连续剪辑角色 |
| `timeline.trackMenu.expandAudio` | 展开底层关联音频轨 |
| `source.drag.both` | 拖动当前原片声画范围 |
| `timeline.placementPreview` | 实际追加／插入的成片位置与时长 |
| `timeline.placementShift.<clip>` | 后续片段的顺延轮廓 |
| `timeline.clip.<id>.sourceRange` | 该片段的原片与成片坐标 |
| `timeline.editingTrack.sourceTime` | 当前成片位置对应的原片时间 |
| `source.coordinateTime` / `program.coordinateTime` | 源／节目监视器的坐标标签 |

## 验证与限制

通过用户已确认的 `Session::execute` 边界测试：8–16 秒→成片 0–8 秒；30–36 秒远端空白落点→8–14 秒；20–23 秒插入→8–11 秒且后段→11–17 秒，视频、关联声音、来源、一次撤销与重做均一致。另验证纯预览不改工程／历史、无关 sync-lock 轨不移动、多声道保留不占用 A2、锁定关联音轨拒绝预览和提交，以及真实磁盘保存后新 Session 重开、继续插入和 Match Frame 原片坐标。

已执行 `cargo test --offline -p filmcraft-engine contiguous_`（5 通过）、`placement`（23 通过）、`place_items_tests`（7 通过），以及受影响界面的 `cargo check --offline -p filmcraft-ui-egui`。复用共享 target 时发现不同工作树的 Cargo mtime 缓存可串用同名 crate；最终界面检查刷新当前树入口时间戳后完整通过。新增回归的主要能力均取得明确 red→green：缺少目标命令、缺少预览命令、保留声音未登记独立目的轨、锁定声音仍允许预览，以及清除后重新接管遗漏额外关联声音。磁盘重开用例同时验证既有保存链路对新字段的支持。
