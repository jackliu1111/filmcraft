## #22 连续剪辑轨与实际导出

原生界面中将空序列的 V1 设为剪辑目标，依次拖入原片 8–16 秒、30–36 秒，再在两段边界插入 20–23 秒。实际顺序为 8–16、20–23、30–36 秒，总长 17 秒；视频及关联音频范围一致。一次撤销／重做恢复完整插入及后续顺延。保存后退出进程、重新启动，目标轨角色、声画片段和时长保持一致。

原生默认快速导出得到 640×360、30 fps、510 帧 H.264 及 48 kHz 双声道 AAC；音视频完整解码成功。另一次导出提交后，先确认任务仍在运行，再删除时间线首段；该导出与未修改工程的导出在六个边界采样画面完全相同，证明本次任务使用提交时快照。

按输入视频真实 PTS 核对各段首尾帧，六处解码画面均与预期源帧接近（有损编码 RGB 平均误差 4.98–7.87）。三个音频片段内部与原音相关系数为 0.887、0.899、0.932，峰值偏移 0–0.333 ms。该代理素材首帧 PTS 为 0.033008 秒，不能用“原片秒数乘帧率”假定首帧从零起算；本次核对采用实际帧 PTS。

证据：`22-native.fcproj`、`22-export-live-edit-snapshot.json`、`22-media-audit.json`、`native-default-22.mp4` 和 `native-default-22-snapshot.mp4`，均在本地忽略目录。
