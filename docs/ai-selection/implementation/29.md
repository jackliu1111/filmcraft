# #29：全部声音事件投影与两种时间坐标

2026-10-16，分支 `codex/event-mapping-29`，从集成 `665e8a21` 起步。原生操作与真实预览由主任务组合验收；本记录不以编译代替界面验收。

## 数据边界

- 声音事件仍只保存在原录像识别结果中。时间线只保存既有原生片段的素材、原片区间、成片区间及关联信息。
- 成片事件是每次查询／绘制时计算的投影；不用第二份人工标记或 `used` 布尔值。手动范围不产生新的模型事件，也不限制片段应显示的事件类别。
- 连续编辑轨与其他原生轨上的普通片段都可投影。关联声画伙伴在查询中合为一次使用，返回各个实际 clip/track ID；重复加入的独立单元各自保留映射。
- 原片子行仍按原片时间显示枪声／人声；没有新增分离音轨或声音导出。

## 公共接口

通过 `engine.execute {command:命令名,params:{…}}` 调用，所有时间为原生 Tick。

- `timeline.eventMapping {}`：返回当前序列的动态映射。每项包含 `item/resultId/category/eventId`、完整原始事件 `eventStart/eventEnd`、被片段覆盖的 `sourceStart/sourceEnd`、实际成片 `sequenceStart/sequenceEnd`，以及 `clips/tracks/link`。
- `timeline.coordinates {time:Tick}`（缺省当前节目播放头）：返回该成片位置的 `positions`，其中 `sequenceTime/sourceTime/item/clips/tracks/link` 明确区分坐标。`timeline.coordinates {item,sourceTime:Tick}` 返回原片位置的每次使用；定格帧通过可选 `sequenceEnd` 表达整段对应区间。
- `selection.usage` 继续从原生片段计算，复用同一个来源覆盖函数；关联声画／多声音输出只算一次，多个类别互不抑制。
- 查询不写工程、不增加撤销历史；保存重开只依靠原事件和片段重新得到结果。

## 界面入口

- 每个现有片段底部的两条细色带分别表示枪声（橙）和人声（青）；按实际覆盖的原片区间显示全部事件。悬停提供原片、成片以及完整原事件区间，不夺取原生片段拖动／裁边操作。
- 自动化 ID：`timeline.event.<clip>.<category>.<eventId>`、`timeline.clip.<clip>.coordinates`。折叠的关联声音仍在同一个剪辑行内；展开音频仍沿用原生行，没有新增分类分离轨。
- 原片头部 `recognition.coordinates` 和成片头部 `timeline.coordinates` 显示当前操作区域的坐标及对应位置；悬停只更新文字，不定位媒体。点击原片事件使用既有源预览，点击成片时间尺使用既有节目预览；原生 F（Match Frame）从节目位置回原片。
- 底层坐标沿用原生 `source_time_at` 的速度、反向、定格规则。事件投影与之对应；没有额外解释原生尚不参与该函数的时间重映射关键帧。
