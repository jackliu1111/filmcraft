# #26：拖拽当前待剪范围加入连续剪辑轨

2026-10-16。分支 `codex/drag-ai-selections-26`。本记录区分代码/自动回归与真实原生操作，不据编译结果关闭工单。

## 行为和复用

- 识别事件或手动范围主体发起原生 `SourceDrag`，在开始时捕获 `item/sourceIn/duration`。附带当前工程、序列、角色轨和媒体映射签名；后续范围调整不改该快照，切换工程/序列或改变素材映射会拒绝旧载荷。
- 目标继续使用 #22 的连续声画轨、原生 `timeline.place` 单素材处理器及同一个放置 planner。空白追加末尾，靠近内容取剪辑边界插入并顺延；不创建新的 V2/A2 轨道对，不合并重复区间。
- 复用原生半透明时长轮廓、实际落点和插入位移反馈；提交后显示 650 ms 淡出轮廓。原片参照不进入渲染，模型事件与待剪范围不被放置修改。
- 范围控件拥有键盘焦点时，Shift+Enter 捕获当前范围并追加到同一轨道；文本输入、其他控件或进行中的鼠标范围调整不响应。没有指定剪辑轨时显示明确状态。
- Escape 复用原生拖拽取消；无效落点不提交。范围载荷不会被素材箱当作原片移动，也不会落到空时间线时变成整段原片。
- 使用情况根据当前序列的真实 TrackItem 原片区间派生，关联声画/多声音输出按 link 单元去重。只显示未使用、部分重叠、已使用提示，允许重复；没有保存易漂移的使用布尔值。
- 新片段的 `item/sourceIn/duration/link` 本来就随原生工程保存，作为原片到成片的来源关系。播放速度使用原生 `source_out()`，定格帧单独处理。完整事件投影、复杂时间重映射与详细跨轨映射仍由 #29 验收。

## 公共入口

调用方式为 `engine.execute {command:命令名,params:{…}}`：

- `selection.capture {item,rangeId}` → 独立 Snapshot；是查询，不增加历史。Snapshot 中包含源范围与运行时上下文，不作为工程中的持久状态。
- `selection.planPlacement {snapshot,time}` / `{snapshot,append:true}` → 原生放置计划（含顺延），不增加历史。
- `selection.place {snapshot,time}` / `{snapshot,append:true}` → 原生片段 ID，整个放置和顺延一次撤销。
- 可选 `track/audioTrack` 必须与快照指定轨一致，不能创建新轨或改投其他轨。
- `selection.usage {item,rangeId}` 或 `{item,start,duration}` → `{status:unused|partial|used,uses,covered,total}`；时间为 Tick，`uses` 计算逻辑使用次数，声画伙伴不重复计数。

已有 `selection.inspect/setRange/addRange` 行为保持；使用情况单独查询，以免把动态派生值误当作范围本身的修改。

## 原生复现

1. 打开已识别录像工程，确认空序列已有 `Use as Editing Track (A/V)` 角色。
2. 在原片分类子行选中范围，找到 `selection.<category>.<rangeId>.body`；左右边界仍使用 `.start/.end`。
3. 从主体拖到 `timeline.track.V1` 的连续剪辑行，观察 `timeline.placementPreview` 和 `timeline.selectionPartnerPreview` 和 `timeline.placementShift.<clip>`，松手提交；Escape 或拖到其他区域不提交。
4. 范围仍拥有焦点时 Shift+Enter 追加。悬停提示和拖拽浮层显示当前使用情况；重复允许，不弹出阻断确认。
5. 修改待剪范围，先撤销范围改动，再撤销前一次放置。保存/重开后，来源映射和使用提示按实际片段恢复。
