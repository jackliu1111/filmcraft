# #28 多素材分析队列、取消、失败与恢复

2026-10-16。专用分支 `codex/analysis-queue-28`。复用已有单素材 NDJSON 桥及共享 ModelService，桌面同时只启动一个桥接 worker；没有复制模型或另建导出队列。每个请求仍沿用现有进程生命周期，不宣称提供跨请求常驻模型。原生混合任务实测由集成联调记录，本分支不据静态检查关闭工单。

## 队列行为

每次导入立即登记全部录像，按导入顺序领取就绪项目。单轨探测后自动分析；多轨停在 `waiting_audio`，可以单独试听、确认后再进入就绪前沿；待选择项不阻塞后续已就绪素材。多个已确认项仍按原导入顺序处理。同一素材、canonical path、大小、修改时间组成的请求去重；重试复用 job ID 并增加 attempt，来源不同但 Item ID 被重用时会建立新请求。

项目记录 `queued`、`probing`、`waiting_audio`、`running`、`completed`、`cancelled`、`failed`、`unavailable`、`interrupted` 及原因，完成零事件仍是 completed。运行时保留独立 job／attempt／工程 incarnation；弹窗选择、原片预览和音轨试听不改变运行任务的接收目标。完成只通过已有 `recognition.attach` 关联到原素材和初始化独立范围，不生成片段或替换人工剪辑。

取消排队项立即终止其请求；取消运行项先撤销接收令牌，再停止已有进程。旧尝试的结果、探测、进度及迟到取消不能修改新尝试。失败／服务退出会留下可见原因，其他任务继续；重试保留已有识别、人工范围与片段。结构化 NDJSON 错误代码保留到队列适配层，缺失运行环境为 unavailable，服务中断为 interrupted，普通执行错误为 failed。

每个 job 捕获 canonical path、文件大小和纳秒修改时间，领取、探测接收、选轨及完成再次核对，并在最终关联时复用原有 source／audio／Origin／token 校验。运行中移除／离线／替换素材会撤销令牌并停止 worker，不阻塞后续素材。旧 job 的“重试”不能接管被另一条路径替换的 Item ID；新素材需独立入队。

队列是工程持久元数据，状态改变不占编辑撤销步，并同步到现有 undo／redo 快照，避免撤销剪辑时复活已取消请求。持久化 revision 正常递增；公开 `project.inspect.editingRevision` 排除纯队列元数据更新，范围拖动使用该 revision，因此后台队列状态不会打断范围预览；真实编辑仍会使旧预览失效。

读取工程时所有未完成状态转换为 interrupted，保存 previous_status；运行令牌不序列化。重开后 `analysis.next` 不会派发这些任务，用户主动重试后才重新读取与分析。队列不依赖进程内旧 imports 缓冲恢复。

## 公共命令

以下均通过 `Session::execute`，状态接收类请求使用 job 和 attempt 防止迟到结果。引擎的 `analysis.start` 只领取任务，桌面适配器负责启动实际 worker。

| 命令 | 参数与结果 |
| --- | --- |
| `analysis.enqueue` | `{item}`，返回去重或新 job |
| `analysis.list` | `{}`，返回持久队列数组 |
| `analysis.next` | `{}`，返回下一个就绪 job；运行中或没有任务时为 null |
| `analysis.start` | `{job,attempt}`，顺序领取，进入 probing 或 running；只允许一个活跃请求 |
| `analysis.probed` | `{job,attempt,media}`，接收真实桥接 media，进入 queued／waiting_audio／unavailable |
| `analysis.selectAudio` | `{job,attempt,audioStream}`，校验后入队；桌面另要求设备实际回报试听播放进度 |
| `analysis.complete` | `{job,attempt,result}`，校验并关联结果；无效结果记录失败，不覆盖已有工作 |
| `analysis.fail` | `{job,attempt,error,code?}`，记录原因并撤销有效接收令牌 |
| `analysis.cancel` | `{job}`，取消请求，保留已有结果 |
| `analysis.retry` | `{job}`，主动重试，attempt 增加并重新读取；不会重复生成片段 |
| `analysis.checkOrigin` | `{job}`，只读核对当前来源身份 |

桌面 UI/control 入口：`apexAi.open {job|item}`、`apexAi.cancel {job}`、`apexAi.retry {job}`；`apexAi.probe {path|item}` 要求素材已导入，`apexAi.analyze` 确认当前待选音轨。同一已排队／运行请求再次确认不会重复提交。

`apexAi.inspect` 返回 queue、selectedJob、activeJob、activeAttempt；每项包含 id、item、attempt、source_path、来源指纹、status、audio_stream、media、error 和最近成功 result_id。队列行自动化 ID：`apexAi.queue.<id>.open`、`.cancel`、`.retry`。试听继续使用 `apexAi.audition.<containerIndex>`、`apexAi.stopAudition`；`apexAi.cancel` 按钮指向实际运行 job，行内取消可处理排队／待选项。

- 公共队列测试从未知 enqueue 失败到通过；补充“缺失服务应不可用”“显式领取必须遵循同一顺序”“元数据不使编辑预览失效”“素材身份变化和 Item ID 复用”均经过失败到通过。
- `cargo test -p filmcraft-engine recognition_tests --lib`：16 项通过，包括 8 项队列及既有识别／多轨接收、保存、取消／迟到保护。验证待选音轨跳过、准确结果归属、有效零事件、失败重试、实际磁盘重开不自启、undo／redo 不复活任务，以及来源替换不能接管。
- `cargo check -p filmcraft-ui-egui` 通过；`selection_` 范围／放置回归 44 项通过；桥接 NDJSON 14 项通过。使用独立 target23 与 3 个编译任务。未运行全仓 CI。
- 同步 #29/#30 后，UI 编译仍通过；识别／队列 16 项、当前范围组稿 5 项、事件映射 5 项回归均通过。`apexAi.apply` 保留 `selection.assemble` 及 `includeVoice` 路径，工程重开恢复组稿来源引用。
- 本分支没有启动真实模型，也没有占用 root 的真实模型数据目录；原生混合任务、取消时进程清理和一次真实失败重试由集成验证。受控双轨素材仅用于机制验证，不能替代真实游戏声／麦克风分轨验收。
