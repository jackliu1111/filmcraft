## 复现入口

1. 使用[当前原生运行与共享引擎配置](../../../integrations/apex-ai/README.md)，以及独立的编辑器`--data-dir`。本轮已有权重、原片及缓存不随Git提供；复现实际识别前先确认相邻后端和模型环境，不能把占位测试素材当真录像。后台关联核对与实际分析共享一个worker；不要同时让另一进程占用同一服务目录。
2. 原生构建、模型运行及自动化回归是不同入口。下面是可重跑的受影响命令，**并非本次文档整理重新执行的结果**：

   ```sh
   CARGO_BUILD_JOBS=3 cargo check --offline -p filmcraft
   cargo test --offline -p filmcraft-engine contiguous_
   cargo test --offline -p filmcraft-engine selection_
   cargo test --offline -p filmcraft-engine recognition_tests
   cargo test --offline -p filmcraft-engine event_mapping_tests
   cargo test --offline -p filmcraft-engine assembly_
   ../apex-voice-detect/.venv-pretrainedsed/bin/python -m unittest discover -s integrations/apex-ai/tests -v
   ```

   使用已配置的Rust／Python环境；可指定独立`CARGO_TARGET_DIR`。没有离线依赖缓存时，`--offline`错误不是产品行为结论。各票实际回归日志及范围见对应实现记录，不合并重复过滤项来夸大用例数。
3. 用本地验收工程的副本恢复检查点。`23-native.fcproj`供双分类／范围；`26-native-manual.fcproj`供补片与拖放；`27-native.fcproj`供受控多轨；`28-native.fcproj`供混合队列；`30-native-evidence.json`内`originalProject/editProject/preservedProject`给出三份确切路径；`31-interrupted.fcproj`及`31-B.fcproj`供恢复／隔离。源媒体仍需可用。本地副本、源内容或结果已经变化时，先记录原因，不能把旧快照当新一次成功。
