## 来源保护缺口

Standards 的硬 P1 与 Spec 的 P2 指向同一个调用链问题，保留各轴原定级：原片在手势开始之前变化时，旧实现把当前素材签名当作新的合法基线，没有核对 AI 范围最初依据的识别来源。

- AI 来源范围捕获时要求 `range.result_id` 对应当前保存的已完成识别记录，核对记录音轨，并复用 `recognition::check_saved` 校验原片路径、文件大小／修改时间、媒体解读／代理、容器与原生音轨映射、结果状态与时间区间。
- 快照带有运行时识别证据摘要。最终预览／提交再次校验该记录与原始来源；原片在捕获前已经变更、捕获后变更或相同文件的分析记录被替换，均拒绝旧 AI 载荷。
- 失败不删除原始事件、人工范围或已有片段，也不增加编辑撤销历史。摘要不进入工程文件；不是第二份可漂移标记。保存范围若仍指向已替换的旧 `result_id`，保留供查看，不能在缺少原分析记录时冒用当前结果作为来源；可选择当前分析范围或独立手绘。
- 手绘范围没有捏造的分析来源，继续使用当前素材与原生拖拽语义，仍保留手势期间的素材签名保护。普通 `timeline.place` 未改动。修改 AI 范围边界不会把它转成无来源的手绘范围。
- 外部分数／缓存缺失与原片变化分开处理。原片和已存事件合法时，`association` 的缓存不可用提示不会禁止已有事件范围的放置。

## 状态建模判断项

接受该维护性判断，在原型范围内做了小型集中整理；未把它描述为已发现的状态迁移缺陷。

- `AnalysisTask.status` 改用 `AnalysisStatus`，集中排队、工作进程、终态、待处理、取消和重试谓词。队列命令、迟到结果保护、工程恢复和 UI 共用这些判定。
- 保存格式仍为 `queued/probing/waiting_audio/running/completed/cancelled/failed/unavailable/interrupted` 字符串。未知旧字符串仍可解码，在重开时转为 `interrupted` 并保留 `previous_status`，不自动启动任务。
- 后端进度阶段与用户提示仍采用原有字符串；没有将进度细节扩成另一套队列状态机。
