# #27 分析音轨选择、原片试听与成片保留声音

2026-10-16。起点为集成分支 `c4463fa5`，专用分支 `codex/multitrack-analysis-27`。本实现不宣称完成工单；用户暂无真实游戏声／麦克风分轨录像，相关真实试听、默认导出及同步验收仍待验证。

## 行为与复用

单音轨沿用导入后自动分析；多音轨探测完成后显示容器音轨编号、名称、声道数和采样率，停在选择状态。每轨的“单独试听”沿用 Source 监视器、媒体池、`MediaSource::audio_stream` 与应用现有音频输出。先预检所选原生音轨解码和输出设备，启动该轨播放、音频设备回报已播放帧后才开放多轨的“确认音轨并分析声音”。停止试听、取消选择和切换工程不改原片、识别结果、片段或成片轨道静音。

试听的原生序号保存在 `SourcePlayback` 运行期状态，并绑定工程 incarnation 与素材 ID；没有修改 `media.interpret`，不会进入工程或影响 Program 混音。切换素材／工程清除试听确认。解码或硬件失败显示明确错误，并阻止把失败试听当作分析确认。试听确认表示已启动原生音频播放且设备回报了播放进度，实际可听性仍需人工核验。

分析选择和保留声音是独立的：`recognition.begin` 只把容器音轨编号传给共享分析桥，模型缓存继续按 source、selected_audio 和 configuration 匹配。普通 `timeline.place` 与旧组稿继续复用原生多音轨放置，默认保留所有可用原音，分别创建原生 `audio_stream` 片段并与画面关联。用户可沿用原生轨道静音或移除，当前没有新增“保留声音”副本状态。

旧组稿的单音轨限制已解除，仍在放置前调用同一映射校验，按全部声音决定 Mono／Stereo 混音，并沿用原生重采样和导出。原片枪声、人声双行没有改变；#24 待剪范围接入保持独立。

## 公共接口和映射

- `recognition.mapAudio {item,media}` 是只读命令。`media` 为桥接 probe 的媒体记录；返回 `audioMapping:[{containerStream,nativeOrdinal,sampleRate,channels,audioStartSeconds}]`、videoOriginSeconds 和 durationSeconds。
- FilmCraft 的 `MediaInfo.audio_streams` 按文件中的可播放音轨顺序排列；ffprobe 的容器音轨序号可以不连续。命令要求两侧完整音轨数量一致、容器序号严格递增且不重复、每路声道及采样率匹配，并核对真实源文件路径／大小／修改时间。数量不一致或无法确定映射时明确拒绝，不能拿容器编号直接当原生 ordinal。
- 多音轨 `recognition.begin {item,audioStream,media}` 必须带已探测媒体，捕获完整映射。`recognition.attach` 再次检查映射和选轨，拒绝分析期间变化或另一轨结果；校验 selected_audio 的起点、音频偏移，以及有记录时 prediction 的偏移一致。
- 仅支持在线、无代理、默认解读的声画素材，原片时长须与原生数据一致。视频起点固定要求 0；非零视频起点明确拒绝。有限的正／负音频起点按视频坐标验证，保留现有模型的 audio-to-video 偏移，不重复平移事件。
- 关联记录新增 `audioMapping`、`analysisAudioOrdinal`，并保留容器 `audioStream` 和完整结果。工程保存重开后，分析选择与实际片段的 `audioStream` 仍独立存在。单轨旧命令／旧结果保持兼容。
- UI/control 命令：`apexAi.audition {audioStream}`、`apexAi.stopAudition`；自动化元素为 `apexAi.audition.<containerIndex>`、`apexAi.stopAudition`、`apexAi.audio.<containerIndex>`、`apexAi.analyze`。`ui.inspect.sourcePlayback.auditionStream` 是运行期原生 ordinal；`apexAi.inspect.auditionedStreams` 是设备已回报播放进度的容器序号。
