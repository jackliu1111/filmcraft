# #25 剪辑单元删改、重排与自动合拢

2026-10-16。基于 #22 的持久化剪辑轨角色实现。公共命令回归和编译验证分别记录；原生指针操作、真实媒体播放、进程重启和实际导出仍由集成验收另行确认，未据自动测试关闭远端工单。

## 已实现行为

- 剪辑轨始终以关联声画为一个单元选择和编辑。关闭原生 Linked Selection 或仅列出视频 ID，也不会把该角色的保留音频留在原处；其他原生轨仍使用原有选择规则。
- `edit.clear` 与 `edit.rippleDelete` 删除该角色片段时同步删除关联音频并合拢目标轨。0–8、8–11、11–17 秒删除中段后成为 0–8、8–14 秒；首段再缩短 2 秒成为 0–6、6–12 秒。
- `timeline.trim` 的 regular / ripple 在该角色上统一采用连续裁边。缩短合拢、延长顺延，In / Out 均沿用原生媒体余量、帧网格和最短一帧限制；越过原片范围时返回实际可应用 delta，预览采用相同结果。
- `timeline.move` 在该角色内按最近边界重排：移除原位置的空隙、插入新边界并重新排列后段。普通拖动保留视频、声音、来源、片段 ID 和 link；明确的 `copy:true` / Option 拖动才创建新单元，并把非相邻多选的片段连续复制，不复制选择之间的空隙。
- 原生 Q / W 及对应的裁到播放头命令复用相同目标裁边，保留原 ID；Trim Monitor 同时选中声画两个边界时同一单元只应用一次。其他原生轨不被目标轨合拢规则顺移。
- 所有相关轨道必须存在且解锁。关联音轨锁定时，选择可以保留，但预览和提交都拒绝部分裁边、删除、重排和复制，工程及历史不变。
- 每次成功命令发布一次原生工程编辑事务，复用原生撤销、重做和磁盘保存。原片参照、识别事件及人工待剪范围不在此模块的修改范围内。

## 复用方式与公共接口

`crates/engine/src/contiguous_edit.rs` 仅处理明确具有 `Sequence.editing_track` 角色的轨道。它把该角色的原生 Track 放入隔离快照，调用既有 `ripple_delete_items`、`ripple_trim_group`、`move_items`、`copy_items`，再把结果作为一次事务发布。没有重新实现媒体解码、片段数据、声音同步、历史栈或保存格式。普通原生轨道不进入隔离快照。

已有 `timeline.select`、`timeline.trim`、`timeline.move`、`edit.clear`、`edit.rippleDelete` 是提交入口。新增纯查询：

```text
timeline.planEdit {action:"trim", clip, edge:"in|out", delta|deltaFrames}
timeline.planEdit {action:"move", moves:[{clip,track,time}], copy?:bool}
```

返回 `handled:false` 表示沿用原生轨道行为；目标轨返回 `handled:true`、实际 `delta`、单元 ID 列表及 `clips:[{clip,track,start,duration,sourceIn,item,link}]`。它不修改工程、分配持久 ID 或增加历史。原生拖动预览和提交调用同一个 typed planner；复制预览的 ID 仅供该帧展示，提交会重新校验当前工程并规划。

普通源素材仍使用 #22 的 `timeline.planPlacement` / `timeline.place`。本票只处理已创建的时间线片段，不把原片待剪范围回写为时间线边界。

## 界面与取消

沿用原生主体拖动、边缘拖动、快捷键、焦点、Esc 和一次撤销。拖动期间只显示规划结果，松手才提交。预览同时更新后段位置、原片范围及关联声音波形；`timeline.editPreview.<clip>` 提供规划后的可定位区域，既有 `timeline.clip.<id>` 和 `ui.timeline.locate` 继续可用。

鼠标手势捕获工程实例及活动序列，切换工程或序列后丢弃旧手势。目标轨混选其他原生轨或拖出该编辑行会明确拒绝，避免部分声画被移走。原生明确的滚动、滑移、速度等特殊工具仍沿用自身命令，不在本票冒称为已经全部改造成连续轨操作。

在现有简体中文词典中补充声画关联剪辑轨、原片时间、成片时间、关联声音展开及轨道菜单标签；自动化 ID 和命令 ID 保持稳定。
