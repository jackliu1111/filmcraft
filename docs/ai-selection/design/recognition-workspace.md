## 最终方案

保留 FilmCraft 原有面板布局，在下方主时间线保留原片参照 V1/A1，将枪声、人声识别行作为 A1 下可展开、折叠的分类子行。原片视频、音频及分类子行共用时间尺、缩放和播放头；“源”面板继续负责画面预览，不再承载单独的识别条。用户调整待剪范围后，把高亮主体拖拽复制到同一行“剪辑轨（声画关联）”，每个片段的画面与声音作为同一个编辑单元，按顺序自动拼接；也可在已有片段边界插入，或用当前范围一次组稿。声画合一描述用户操作的剪辑单元与一行展示，不取消源媒体的视频、音频技术区分。主流程为：

**导入录像 → 自动分析 → 展开原片音频轨下的分类高亮 → 预览并调整范围 → 拖拽到剪辑轨并自动拼接 → 原生编辑与导出。**

| 环节 | 已确认的行为 |
| --- | --- |
| 导入与分析 | 单音轨直接分析；多音轨先试听并选择分析音轨。多个素材排队处理，期间可继续预览与编辑。分析完成只展示结果，不自动改时间线 |
| 识别展示 | 首版枪声、人声各一行，位于主时间线原片 A1 下，可展开、折叠；原片 V1/A1 与分类子行共用时间尺、缩放和播放头。子行是分类高亮，不是分离出的枪声或人声音频。人声不区分来源、不做文字转写；编辑片段仍保留原片范围与放置时间的映射 |
| 选择与预览 | 悬停显示轻量控件；单击固定选择并定位原片预览。悬停本身不播放、不改片 |
| 调整范围 | 拖左右手柄调整待剪范围并预览边界帧；原始识别事件保留。默认枪声前后各 5 秒、人声各 1 秒，超出原片部分截断。无高亮处也可手动划选补片 |
| 拖拽创建与拼接 | 拖高亮主体复制关联声画到同一条剪辑轨；拖到空白处或用 Shift+Enter 默认追加末尾。拖到已有片段附近时吸附片段边界插入，后续片段整体顺延，不覆盖已有内容，也不留下空隙。V1/A1 原片参照与分类子行保持不变。不使用添加按钮；显示半透明片段、时长和落点，松手提交并短暂高亮。Esc 或无效落点取消，成功拖入可一步撤销 |
| 片段编辑 | 画面与关联声音一起选择、调整边界及删除；删除或缩短后，后续片段自动合拢，延长时后续片段顺延。撤销同时恢复片段内容与这次产生的位置变化 |
| 编辑独立 | 拖入片段采用当时的待剪范围；随后修改待剪范围不影响已有片段，时间线修改也不回写待剪范围或模型事件 |
| 重复使用 | 手动拖入允许重复使用或原片范围重叠，提示“已使用／部分重叠”，不自动裁减或合并；各次使用在成片中依次拼接，不叠放成多轨画面。提示随时间线实际使用情况更新 |
| 按当前范围生成草稿 | 对当前原片，默认枪声，可选择包含人声。使用人工调整后的待剪范围，未调整项取默认；按原片顺序合并重叠区间。另建组稿原稿并打开编辑副本，保留已有手动剪辑 |
| 保存与继续 | 当前工程保存识别结果关联、人工待剪范围和时间线；其他工程可复用匹配的完成分析，但不继承人工调整。重开恢复已完成内容，中断或排队任务由用户主动继续或重试 |
| 编辑与导出 | 继续使用 FilmCraft 原生编辑、应用内后台导出及其默认参数；不新增本轮未讨论的导出档位 |

“组稿原稿”指一次组稿完成时保留的基准版本，可以包含组稿前的人工范围调整；它不是未经人工调整的模型输出。旧文档中的“AI 原始草稿”沿用这一基准版本含义，见 [术语表](../GLOSSARY.md)。

## 代表性验收场景

以下为设计要求对应的验收场景，不记录执行结果；产品确认不能代替实现验证。

1. **少改布局与共用时间尺**：打开已有自定义布局，源预览、节目预览、素材区及时间线位置不被重置；枪声、人声作为 A1 分类子行展开和折叠。缩放或移动播放头时，V1/A1 及识别高亮位置保持对齐；源预览仍可操作且没有另一条识别区。
2. **区分事件与范围**：枪声为 10–12 秒，默认待剪为 5–17 秒，调整到 8–16 秒后，模型事件仍是 10–12 秒，拖动边界能查看对应画面。
3. **声画单元、自动拼接与独立修改**：将原片 8–16 秒拖到空剪辑轨，得到成片 0–8 秒的单个关联声画片段；再将 30–36 秒拖到轨道空白处或用 Shift+Enter 加入，紧接为成片 8–14 秒，仍只有一条剪辑轨。把原片 20–23 秒拖到两段之间的边界，则插入成片 8–11 秒，原第二段顺延到 11–17 秒。删除中间段后自动合拢回 0–14 秒；第一段缩短 2 秒后，第二段起点同步提前 2 秒。全程 V1/A1 原片不变。再把原待剪范围改成 7–18 秒，已加入片段仍保留自己的范围；撤销创建或删改同时恢复关联声画和本次位置变化。
4. **手动重复与自动合并**：原片范围 10–20 秒和 15–25 秒分别手动拖入，在同一剪辑轨连续拼接为 20 秒，保留重复内容并提示原片范围重叠；用这两个当前范围组稿，则合并为原片 10–25 秒的 15 秒片段。自动拼接不等于自动去重。
5. **当前范围组稿**：调整过的范围不恢复默认；新原稿反映组稿时的当前范围，编辑副本后续删改不改变该原稿，原有手动时间线保留。
6. **保存与隔离**：保存重开后，恢复同一工程的已完成识别、待剪范围及时间线；在另一工程使用同一原片，可复用分析，但不带入上一工程的人工边界调整。
7. **任务与失败**：多音轨需先选分析音轨，素材排队时编辑不阻塞；取消、失败、离线或无音轨不破坏既有剪辑。应用重开不擅自重新启动中断分析，也不把中断显示为没有声音。
8. **效果与效率**：真实样本分别核验枪声、人声区间和声画范围，记录漏检、误检及补片成本；用相同素材比较旧流程与新流程的操作步骤、误操作和完成时间。人声效果、长录像性能和多音轨剪辑链路均标记为待验证。

## 用户提出的方向

- 在 FilmCraft 原有布局中完善 AI 识别与选片界面，尽量减少调整。用户第二轮已用这一要求修订最初的“全新界面”方向。
- 导入视频后自动进行音频识别。
- 按声音类别分行展示识别结果，例如枪声、人声等，并高亮相应区间。
- 鼠标移入高亮区间时显示操作控件，可调整左右边界；创建片段采用带可视反馈的拖拽操作，不使用“添加片段”按钮。
- 通过简化片段选择和长度调整，提高切片效率。

以上意图已收敛为本文开头的最终方案。下方保留源码依据和分轮决策记录，避免将早期建议当成最终决定。

## 设计讨论时的源码依据（历史记录）

以下依据来自本轮改造前的原型和固定上游，仅解释设计选择，不记录本轮实现进展。

- 基线 FilmCraft 原型通过本机 Python 桥复用 `ModelService`，将枪声候选组装为连续草稿；探测后自动选择唯一音轨，多音轨需用户选择，分析需点击生成按钮。旧入口随 [固定上游补丁](../../../integrations/apex-ai/reference/apex-ai.patch) 提交。Q3 决定将新流程改为分析后展示高亮，组稿由用户主动发起。
- [model_inference.py](https://github.com/jackliu1111/apex-fps-mvp/blob/978fed1580fdf85d34e2b5c17f973693c5510693/model_inference.py) 保存完整类别分数。最初核查的本机预测包含 447 类，其中有人声相关类别；基线 [model_service.py](https://github.com/jackliu1111/apex-fps-mvp/blob/978fed1580fdf85d34e2b5c17f973693c5510693/model_service.py) 的区间后处理只消费两类枪声分数。读取人声分数不等于完成候选区间的提取与效果验证，也不等于语音转文字或区分说话人。
- 识别事件与待剪范围分别保留，定义见 [GLOSSARY.md](../GLOSSARY.md)，边界见 [ADR 0004](../decisions/0004-separate-recognition-events-and-clip-selection.md)。[ADR 0003](../decisions/0003-preserve-ai-draft-and-editing-copy.md) 继续约束主动生成的组稿原稿与编辑副本。
- FilmCraft 上游提供关联视频／音频放置、边界调整和回原片定位：`crates/engine/src/commands.rs` 的 `timeline.place`、`timeline.trim`、`sequence.matchFrame`，以及 `crates/engine/src/source_monitor.rs` 的 `source.open`。这些能力可供新流程复用。
- 默认 Editing 布局包括源监视器、节目监视器、属性区、素材区与下方时间线，用户可自定义；因此增加控件不应重置面板分栏。源码入口为 `crates/ui-egui/src/dock.rs` 与 `panels/monitor.rs`。
- 上游 `panels/source_drag.rs` 携带原片和起止范围，`panels/mod.rs` 与 `panels/timeline.rs` 显示跟随指针的标签、时长及半透明落点框，并支持 Esc 取消。核查时原生拖入默认覆盖，按 Command 才插入；Q16 选择由目标剪辑轨决定自动拼接方式，其他原生轨道保留自己的编辑语义，见 [ADR 0005](../decisions/0005-target-track-controls-contiguous-editing.md)。

## 最后一轮已确认决策

用户先在 Q14 的解释中选择 **B：按当前范围组稿**，随后以“其余默认”接受 Q12、Q13、Q14 配套及 Q15。已调整的片段使用新范围，未调整的片段使用默认范围。例如枪声发生于 10–12 秒、默认留白后为 5–17 秒，用户改为 8–16 秒，则组稿采用 8–16 秒，不恢复到 5–17 秒。

界面动作命名为“按当前范围生成草稿”。组稿输入可能包含人工调整，不能把生成结果描述为“未经人工调整的纯 AI 结果”。这不修改底层识别事件，也不引入另一套草稿生命周期；保留基准版本与编辑副本，见 ADR 0003。

| 编号 | 边界 | 已确认决定 |
| --- | --- | --- |
| Q12 | 拖入后继续改范围，是否联动已剪片段 | 拖入时形成独立剪辑片段。之后修改原片待剪范围只影响下一次拖入；时间线剪辑不回写识别区间或待剪范围。声画片段保持关联，拖入可一步撤销 |
| Q13 | 跨类别重叠与重复使用 | 枪声与人声在原片上分别保留。允许同一范围重复拖入，提示已使用及重叠情况，但不自动合并或裁掉手动选择；成片可能包含重复画面。提示随时间线实际使用情况更新 |
| Q14 | 组稿范围的取值 | **已确认 B**：使用当前待剪范围；已调整的用新值，未调整的用默认值。替代原先“忽略人工调整”的建议 |
| Q14 配套 | 类别、重叠与新稿保存 | 当前原片默认仅枪声，可选择包含人声；将采用当前边界的范围按源时间合并重叠，另建组稿原稿并打开编辑副本，保留已有手动剪辑 |
| Q15 | 保存、重开及跨项目复用 | 当前工程保存识别结果关联、人工待剪范围和时间线；同一原片的完成分析可复用，人工调整只属于当前工程。重开直接恢复已完成内容，中断或排队任务由用户主动继续或重试，不自动后台续跑 |

## 原型试用后的修订

用户保留 A 的枪声、人声双行呈现，要求把识别与剪辑操作集中到下方主时间线。此前 Q11 的源监视器位置由试用反馈取代；B/C 局部呈现对照退休，旧版仅在本机临时分支提交 `d3f2506` 中留档。随后用户指出：“创建的剪辑画面和关联声音应该在一个轨道（维度），并且自动拼接吧？这个和正常视频剪辑的逻辑不一样”。因此，此前新增 V2/A2、V3/A3 并按轨道对插入的方案仅作为历史，当前改为一条剪辑轨自动拼接。设计保留单一 A 入口，不需要方案切换浮条。

- 原片 V1/A1 始终作为参照，A1 下展开枪声和人声分类子行；这些子行不产生独立声音素材或混音轨道。
- 原片与分类高亮使用原片时间，剪辑轨使用成片时间；保留同一主时间线布局和共用缩放。Q19 后续明确按操作区域显示活动时间，并标出对应原片位置，不能把一个数值同时当作两种时间。
- 拖拽高亮主体复制当前待剪范围的关联声画到同一剪辑轨，声画作为一个单元显示、选中、调整和删除。空白落点或 Shift+Enter 追加末尾；已有片段附近的落点吸附片段边界插入，后续整体顺延。删除或缩短自动合拢，原片参照不变。
- Q12 的范围独立、Q13 的重复提示、Q14 B 的当前范围组稿及 Q15 的工程隔离与恢复规则继续有效。旧自动组稿基准和编辑副本规则保持。

上述试用反馈形成最新设计约定。旧 A/B/C 或多轨方案的检查记录不能证明新方案满足验收要求；本分支同步了对应网页原型，实际浏览器检查范围见 [CAPTURE.md](../../../prototypes/ai-selection/CAPTURE.md)，原生代码修改单独保留。

## 实现与验收的边界

以下是支持上述设计的基本保障与验证工作，不通过访谈虚构已实现能力：

- 沿用原生预览、播放、缩放、时间线与撤销能力；识别行显示类别名称，状态不单靠颜色，边界操作保留键盘替代。具体布局尺寸、命中区域和动效时长由交互验证确定。
- 任务失败、取消、无可分析音轨或素材离线时，保留已有剪辑及人工调整，并明确未完成或不可用状态；不把尚未分析、失败或无可用数据显示为“没有声音”。
- 验证真实枪声和人声样本的区间效果、长录像中识别子行的浏览与共用缩放、主时间线可用空间、拖边界和拖主体的区分、有效与无效落点、同一剪辑轨追加、边界插入与后续顺延、删除和缩短后自动合拢、声画关联及一次撤销。
- 用同一段录像比较当前流程与新流程的定位、调边界、拖入、补漏和重开继续操作；记录操作步骤、误操作和完成时间，不预先承诺效率倍数。
- 不因本次界面设计扩展到文字转写、说话人分离、精彩程度判断、跨重启无人值守服务或完整发行版迁移。人声效果与多音轨编辑链路须按新范围独立验证，不能沿用旧单音轨验收结论。

Q1–Q15 及单轨拼接方向已有明确选择。用户在下述优化讨论中重新提出原生交互兼容、导入后识别细节的同步与顺序问题，随后由 Q16–Q19 确认边界；下方保留澄清过程。

## 单轨原型后的优化讨论（历史记录）

2026-10-13，用户确认“就是当前设计”，保留声画关联单轨与自动拼接方向；当时先讨论优化，不修改原型代码。后续 Q16–Q19 已收口，以下保留当时的讨论过程。

当时的讨论约束：新增 AI 操作与动画需要检查同 FilmCraft 原生操作的冲突；存在冲突时，依据用户已有操作习惯权衡，不能仅为增加动效改变操作结果。用户还提出“导入画面的时候，同步顺序导出枪声、人声细节”；这句话当时待澄清，后由 Q17 确认为事件展示与剪辑映射，不是流式识别、类别声音分离或最终成片导出。下表保留当时的讨论提纲。

| 待讨论边界 | 需要用具体场景确定的内容 |
| --- | --- |
| 自动拼接的适用范围 | 同一剪辑轨接收 AI 高亮与普通素材时是否采用相同行为；与原生默认覆盖、修饰键插入的差异如何让用户预知 |
| 操作与动效 | 选择、拖主体、拖边界、空白划选、插入预览、取消和撤销的优先级；动效必须准确表达落点及后续位移，不能只表现鼠标落下的位置 |
| 导入与结果顺序 | “同步顺序导出细节”指导入后结果展示、剪辑中的声音与标记映射，还是最终导出；确认后再决定分段展示与完成状态的规则 |
| 声画与标记映射 | 分析音轨与成片保留音轨的关系；原片事件进入剪辑片段后的时间映射、裁边和重复使用如何表达；不因枪声、人声分类自动推定为分离音轨 |
| 真实验证 | 区分交互演示、真实识别和实际声画导出；人声候选、多音轨及非零媒体起点等不能复用旧单音轨样片结论 |

当时只读核查发现的浏览器缺口：已剪片段主体只能选中，尚无拖动重排；撤销历史只保存剪辑序列，不包含待剪范围修改，因此“先拖入、再改待剪范围、再撤销”会撤销更早的插入。手动片段只关联被拖入的事件，没有展示该原片范围内所有枪声、人声事件的成片位置。这些是演示阶段的缺口，不是正式行为约定；人工编辑的撤销范围、已剪片段重排、键盘焦点与完整事件映射应纳入后续实现及验收。

该阶段仅记录用户已确认的方向与待讨论边界，推荐方案在后续确认后写入“已确认的行为”。普通动效参数不新增 ADR，只有影响长期边界且存在真实替代方案的决定才记录 ADR。

### 原生改造前收口

2026-10-13 后续，用户表示当前原型比较符合改造需求，要求开始改造并提出仍需讨论的信息。当前原型可作为本轮原生改造的设计基线；此前“只讨论优化”描述上一轮，并非继续禁止准备改造。Q1–Q15、双识别子行与声画单轨自动拼接方向不重新开放。用户随后答复“全部默认”，接受 Q16–Q19 的全部推荐并确认开始改造。下列行为已确认，原生实现与验证另行记录，不以产品确认代替验收。

| 已确认边界 | Q16–Q19 决定 |
| --- | --- |
| Q16 自动拼接适用范围 | 行为由目标剪辑轨决定；普通素材和 AI 待剪范围拖入同一剪辑轨，都采用追加、边界插入顺延及删除后合拢。其他原生轨道保持其编辑方式 |
| Q17 声音细节的含义 | 分析完成后按原片时间展示两类事件；剪辑范围内全部枪声、人声事件映射到成片位置，随裁短、重排、重复使用更新。本次不指独立声音导出或流式识别 |
| Q18 分析音轨与保留音轨 | 分析音轨只决定模型输入；剪辑默认保留原有声音，由用户主动静音或移除。选择游戏声音分析不隐含丢弃麦克风或队伍语音 |
| Q19 共用时间尺中的时间含义 | 保留布局和共用缩放，按操作区域明确显示原片或成片时间，并标出对应的原片位置。例如成片第 9 秒对应原片第 31 秒时分别标示，不把两种坐标混成同一时刻 |

本次收口确认产品行为，不代表原型已覆盖全部约定。网页演示与其浏览器检查记录随本分支同步；本轮原生改造与原生验收结果独立记录，不随本分支提交。
